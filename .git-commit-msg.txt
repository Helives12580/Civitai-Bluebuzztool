改用游标推进取图：彻底解决重复反应白点

上一版用「已点过的图片 ID 集合」去重，有两个问题：

1. 集合无限膨胀（已积累 151 个还在涨）
2. 历史回溯受流水查询 limit 200 截断，实际漏掉了更早的图
   —— 实测补漏执行时那 4 张仍然撞上了漏网的历史图

改成单调推进的游标（思路来自 Helives）：
每次只取 id 大于游标的图，按 id 升序点完，游标前移到最后那张。
状态恒为一个数字，天然不重复。

依据是 /api/v1/images?sort=Oldest 返回严格按 id 升序
（实测 2717, 2795, 2796, 2968...），而 sort=Newest 的顺序并不稳定，
所以本地按 id 排序后再推进，不依赖接口返回顺序。

配套改动：

- listImages 增加退避重试。该接口约 50% 概率返回 503
  ("Image search is temporarily overloaded")，实测重试即成功；
  503 失败时明确报「站点过载」，而不是含糊的「无法执行反应任务」
- 保留今日流水排除，补游标的盲区（用户手动点的赞不经过游标）
- 删掉被取代的 reactedIds 集合方法与 shuffle

今日实测对比（同一账号）：

- 修复前：50 次反应，14 笔到账（28%）
- 修复后：50 次反应，49 笔到账（98%）
- 站点真值 143 buzz = 98(反应) + 20(关注) + 25(领取)
